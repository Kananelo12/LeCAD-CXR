# 0003 — API implementation choices

**Status:** accepted · **Date:** 2026-10-10

## Context

ADR 0001 fixed the architecture (FastAPI, httpOnly cookie, hash-chained
audit log). Building it raised smaller choices, recorded here so they can
be defended or revisited.

## Decisions

**A fake model until a real one exists.** `LECAD_FAKE_MODEL=1` serves
random but repeatable findings so sign-in, upload, audit and the web app
can be built and tested before training finishes. It announces itself:
the model version is `FAKE-not-a-trained-model` and the disclaimer begins
with a warning. The service refuses to start with both or neither of
the fake model and a checkpoint configured.

**Checkpoints load with `torch.load(weights_only=True)`.** The checkpoint
holds tensors and plain values only, so a tampered file cannot execute
code on load. The served model version is the architecture plus the first
12 characters of the checkpoint file's SHA-256, so every audit row names
the exact weights.

**Grad-CAM is implemented in the service (about 15 lines)** rather than
through the `grad-cam` package, keeping the serving install small. Heatmaps
are computed in the same request, for up to five flagged findings, because
the image is not kept for a later request.

**PyJWT instead of python-jose.** python-jose is effectively unmaintained
and has had security advisories; PyJWT is maintained and does the same job.

**Sessions: 30 minutes, sliding.** A request after half the lifetime
renews the cookie, so an active clinician is not signed out mid-task and
an idle session ends. Each request reloads the user, so deactivating an
account takes effect at once.

**Sign-in throttle.** Five failures per username in 15 minutes returns
429. A wrong username and a wrong password give the same response in the
same time (a dummy hash is checked for unknown users), so the API does not
reveal which accounts exist.

**Uploads are judged by content.** The file is decoded and must be PNG or
JPEG regardless of its name or declared type; images over 50 megapixels
are refused before decoding (decompression bombs).

**Append-only is enforced twice.** On PostgreSQL a trigger rejects any
UPDATE, DELETE or TRUNCATE of `audit_log`. On any database the hash
chain detects edits and deletions, except deletion of the newest rows,
which needs a head hash recorded outside the database
(`admin verify-audit` prints it). Concurrent writers are serialised with
a PostgreSQL advisory lock, tested by disabling the in-process lock.

**SQLite is allowed for tests and quick local runs.** PostgreSQL remains
the deployment database; its specific safeguards have their own tests.

## Consequences

- Tables are created on startup. Schema changes after deployment need
  migrations (Alembic), not yet set up.
- The throttle is in memory, per process.
- Training now records `n_images` in the validation metrics, for `/model`.
- `lecad.config.PATHS` is resolved on first use, so the API can import
  shared code on a machine without the dataset.
